# GOVERNANCE-UX-CHARTER

Version 1.0

Purpose

이 문서는 Data Relay의 Governance UX 설계 기준 문서이다.

Governance 기능은 이미 구현된 엔진(M5~M12)을 사용자에게 어떻게 보여줄 것인가를 정의한다.

이 문서는

* Governance가 무엇인지
* 어디에서 설정하는지
* 어디에서 운영하는지
* 사용자에게 무엇을 보여줄지

를 정의한다.

---

# 1. Governance Product Philosophy

Governance는 Compliance Product가 아니다.

Governance는 Data Control Capability이다.

사용자의 목적은 다음과 같다.

```text
이 데이터를 보내도 되는가?

보낸다면 어떻게 보호할 것인가?

문제가 발생하면 어떻게 처리할 것인가?
```

사용자는

* Protection Engine
* Identity Vault
* Classification Engine
* Policy Engine

같은 내부 엔진을 이해할 필요가 없다.

Governance UX는

엔진 중심

이 아니라

사용자 목적 중심

이어야 한다.

---

# 2. Governance Mental Model

사용자는 아래 순서로 생각한다.

```text
1. 데이터를 가져온다

2. 데이터를 매핑한다

3. 데이터를 확인한다

4. 민감 데이터가 있는가?

5. 보호가 필요한가?

6. 보내도 되는가?

7. 목적지로 보낸다
```

Governance는

Mapping 이후

Destination 이전

단계에서만 의미가 있다.

---

# 3. Governance Is Optional

Governance는 기본 Wizard Step이 아니다.

기본 Wizard는

```text
Connect

Mapping

Destination

Review
```

이다.

대부분의 사용자는 Governance 기능이 필요하지 않다.

---

Governance는

Advanced Feature

로 활성화된다.

예:

```text
Advanced Features

[ ] Data Governance
```

사용자가 활성화하면

Wizard가 동적으로 확장된다.

---

비활성화 상태

```text
Connect

Mapping

Destination

Review
```

---

활성화 상태

```text
Connect

Mapping

Governance

Destination

Review
```

---

원칙

```text
Simple First

Advanced On Demand
```

---

# 4. Governance Step Design

Governance Step은

엔진 설정 화면이 아니다.

다음과 같은 UI는 금지한다.

```text
Sensitive Detection

Identity Vault

Policy Engine

Classification

Quarantine

Protection Engine
```

---

Governance Step은

사용자 목적 중심

구조를 사용한다.

---

## Section A

Detect Sensitive Data

```text
[ ] Email Address

[ ] IP Address

[ ] Credit Card

[ ] API Key

[ ] Custom Pattern
```

---

## Section B

Protect Sensitive Data

```text
( ) Audit Only

( ) Mask

( ) Tokenize

( ) Drop
```

---

## Section C

Control Delivery

```text
When Sensitive Data Detected

( ) Continue

( ) Route To Secure Destination

( ) Quarantine

( ) Stop Delivery
```

---

사용자는

무엇을 할 것인가

만 결정한다.

어떤 엔진이 실행되는지는 숨긴다.

---

# 5. Governance Complexity Rule

Governance는 기본적으로

Simple Mode

로 시작한다.

---

Simple Mode

```text
Detect

Protect

Control
```

---

Advanced Mode

```text
Custom Pattern

Custom Routing

Approval Workflow

Exception Handling

Retention Rules
```

---

기본 사용자에게

Advanced 옵션을 노출하지 않는다.

---

# 6. Governance Dashboard Philosophy

Governance 메뉴는

설정 페이지가 아니다.

Governance 메뉴는

운영 페이지이다.

---

설정

```text
Wizard
```

---

운영

```text
Governance Dashboard
```

---

원칙

```text
Configuration happens in Wizard

Operations happen in Governance
```

---

Governance Dashboard는

현재 상태를 보여준다.

```

---

```

---

---

# 8. Stream-Centric Governance

Governance는

Global First

가 아니라

Stream First

이다.

---

예

```text
AWS CloudTrail Stream

→ Audit Only
```

---

```text
HR Database Stream

→ Tokenize
```

---

```text
Finance Stream

→ Quarantine
```

---

Governance 설정은

각 Stream마다 독립적으로 가진다.

---

# 9. Advanced Governance Features

다음 기능은

Advanced Governance

범주에 속한다.

```text
Approval Workflow

Custom Pattern Detection

Exception Lists

Retention Policies

Multi-Level Review
```

---

기본 Wizard에서는 숨긴다.

사용자가 Advanced Governance를 활성화할 때만 노출한다.

---

# 10. Governance UX Rules

Rule 1

Governance는 기본 Wizard Step이 아니다.

---

Rule 2

Governance는 사용자가 활성화해야 나타난다.

---

Rule 3

Governance는 엔진 중심 UI를 금지한다.

---

Rule 4

Governance는 사용자 목적 중심 UI를 사용한다.

---

Rule 5

설정은 Wizard에서 한다.

---

Rule 6

운영은 Governance Dashboard에서 한다.

---

Rule 7

기본 사용자에게 Advanced Governance를 노출하지 않는다.

---

# Final UX Principle

```text
Governance is not a product.

Governance is an optional capability.

Users do not configure engines.

Users define data handling intent.

Configuration belongs to the Stream Wizard.

Operations belong to the Governance Dashboard.
```


---

# 11. Route Based Governance

Governance는

One Stream
↓
Many Routes
↓
Many Destinations

아키텍처를 따른다.

---

Route

=

Destination Specific Processing Unit

---

동일 Stream이라도

Route마다

다른 Governance 정책을 가질 수 있다.

예:

```text
Office365 Stream

Route A
→ Syslog
→ Audit Only

Route B
→ SaaS XDR
→ Mask

Route C
→ Data Lake
→ Tokenize
```

---

사용자는

Destination별 처리를 위해

별도 Stream을 생성하지 않는다.

Route를 사용한다.

---

# 12. Destination First Governance

사용자 사고 순서

```text
1. 데이터를 가져온다

2. 목적지를 선택한다

3. Route를 구성한다

4. Governance를 결정한다

5. 데이터를 보낸다
```

---

Governance는

Destination 선택 이후

Route Processing 과정에서 구성된다.

---

# 13. Route Aware Governance Dashboard

Governance Dashboard는

Stream 뿐 아니라

Route 관점도 제공해야 한다.

---

예

```text
Office365 Stream

Route A
Syslog
Audit Only

Route B
Stellar Cyber
Mask

Route C
Data Lake
Tokenize
```

---

Governance 운영은

Stream

+

Route

관점을 모두 제공한다.

---

# 14. Stream-Centric Governance Extension

Governance는

여전히 Stream First 이다.

---

추가 원칙

```text
Configuration Scope

Stream

Processing Scope

Route
```

---

Execution Unit

Stream

---

Processing Unit

Route

---

- install/publish permission
- trusted publisher/key
- package signature status
- package origin/provenance
- license decision
- validation status
- package lifecycle audit

기존 Governance UX는 Protection / Classification / Policy / Violation / Quarantine / Replay와 같은 데이터 통제를 계속 담당한다.
Marketplace security를 Stream Governance step으로 노출하지 않는다.
